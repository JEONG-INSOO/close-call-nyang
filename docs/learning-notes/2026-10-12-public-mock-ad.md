# 가상 광고를 공개 기능으로 켜되 정상 기록을 유지하기

## 무엇을 바꿨나
사용자가 SDK 없이 DEXCONSULTING 가상 광고와 광고 보고 일어서기를 요청했다. exact true 빌드 플래그면 텍스트 광고를 표시하고, 기존 5초 활성 시청/중도 닫기 무보상/판당1회 부활/카운트다운을 유지한다. 표시 화면은 타이머를 직접 돌려 보상하지 않고 엔진의 남은 시간만 표시한다.

## 왜 이렇게 설계했나
이전 `!flags.mockAdsEnabled`는 광고를 보기 전의 정상 랭킹과 100% 해금까지 차단했다. 기능을 제공하는 것과 보상을 사용한 것은 다르다. 정상 판은 eligible로 시작하고 `!state.run.reviveUsed`일 때만 해금 횟수를 관찰한다. 부활 이후도 기기 최고 점수는 저장하지만 서버 순위/해금에 포함하지 않는다. 부활 전에 100%를 달성한 정상 횟수는 취소하지 않는다.

## 흐름과 함정
처음 실패 tick에서 온라인 proof가 terminal이 된다. 즉시 기록자를 detach하고 pending upload는 보존한다. 부활 뒤 `session.freeze()`를 호출하면 실패 전의 정상 기록도 재전송하지 못하므로 화면·새 tick만 분리한다. 계정 삭제의 freeze 경계는 유지한다. 서버 엔진/규칙은 바꾸지 않아 parity8파일만 검사한다.

## 검증
Jest50스위트716/716, 타입, ranked:check8, release11/11, ranking tools67/67, public27/27 통과. main·scene·mock online3개 번들 재생성, 고정된 최신 main 번들에서 Chromium66시나리오 중55pass/11의도적skip/0fail(5.3분) 확인. dev/production flag, 5초·닫기·background 정지·1회 보상, 정상 해금·부활 이후 해금 제외, 최초 랭킹·대기 업로드, 실제3행 버튼/광고를 검증했다. 코드와 새 번들의 500ms/opt-in/가상 광고 문구 marker도 확인했다. 실제 iPhone Safari는 별도 pending이다.

새 테스트는 처음 두 곳에서 실패했다. 부활 직후에는 1.5초 보호가 남아 있으므로 강제로 실패 각도를 주어도 즉시 결과가 되지 않았다. 실제 보호 시간을 진행한 뒤 실패를 검사한다. 업로드 재시도는 1초 backoff를 존중하므로 상태 전환을 1초보다 넉넉하게 기다린다. 테스트를 통과시키기 위해 보호/서버 backoff 규칙을 지우지 않는다.

전체 검사에서는 기존 ‘production true여도 광고 차단’ 테스트도 새 요구사항과 충돌했다. false/미설정/대문자·공백은 계속 차단하고, 새 true는 요청·취소를 반복해도 보상이 생기지 않음을 별도 검사한다. 단순히 테스트를 삭제하거나 보상 검증을 약화하지 않는다.

첫 전체 브라우저 검사에서도 기존 온라인 시나리오가 광고 버튼0개/결과2행을 기대해 실패했다. 최초 실패의 tick 업로드/finalize 검사는 유지하고 공개 버튼/3행으로 기대를 갱신했다. 광고 브랜드를 정리하려고 검사 중 같은 export 폴더를 재생성한 것은 실수였다. 그 사이 index.html이 없어져 포커스 검사 시작 페이지가 HTTP404로 실패했다. 이는 포커스 로직 실패나 Safari 증거가 아니다. 모든 export가 끝난 뒤 같은 경로를 고정해서 전체 검사를 다시 실행한다.

## 배포 구분
EAS/Pages 설정 true, diagnostics false. 현재 제출된 IPA6과 Apple 소개/광고 설문은 변하지 않는다. 새 네이티브 빌드와 광고 설문·심사 메모 재검토가 후속이다. 공개 개인정보 페이지에는 텍스트 홍보와 SDK/네트워크/추적 없음이라는 실제 동작만 반영한다. 새 계약이 허용한 두 광고 문단과 날짜 이외의 과거 승인 문구는 그대로 검사한다.
