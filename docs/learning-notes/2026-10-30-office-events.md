# 사무실 장면·사표 퇴장·후반 가속

## 왜 바꿨나
사무실은 기존1200px 타일에 책상/복사기와 혼나는 두 사람만 있어서 상황이 반복됐다. 두2400px 타일에 타이핑, 복사기 용지 걸림, 발표, 커피 휴식, 서류 운반, 업무 대화6구역을 고정 배치했다. OfficeWorker는 팔·표정·소품을 pose별 SVG로 그린다. 프레임마다 React 노드나 타이머를 생성하지 않고 기존 transform만 바뀐다. SVG 노드 수가 늘었으므로 iPhone 프레임 성능은 별도 확인해야 한다.

## 사표 내고 뛰는 동료
office 전용 resignation 이벤트를 추가했다. controller가 event.direction과 활성 진행률을 SceneFrame에 전달하고, AnimatedG가 그 방향으로 동료를 화면 가로질러 이동시킨다. 물리도 동일 direction*event.strength를 사용하므로 그림과 힘의 방향이 같다. 예고1.2초/활성0.7초, pause 시 시간 정지. 그림이 엔진 상태를 수정하지 않는다.

## 후반 난이도
eventStrength는 `1.6 + 1.8 * level` (기존계수0.65), speed는 `base * (1 + 1.05 * log1p(extra/85))` (기존0.7). 15%까지 초반은 유지한다. 무상한 로그 곡선이므로100% 이후도 가속/압력이 계속 오른다. 100%까지 약90→83.65활성초. 그림 각도를 강제로 바꾸지 않고 각가속도를 적분하므로 반대 입력으로 대응할 수 있다. 예고/보호/입력력 유지.

## ESC
웹 active 화면에서 ESC는 PAUSE 한 방향만 수행한다. keyboard/touch 입력과 프레임 clock을 지우고, paused 상태에서 다시 눌러도 재개하지 않는다. 폼/모달/키 반복은 제외한다. 실제 재개는 이어하기 버튼으로 한다.

## 검증과 실패에서 배운 점
최종 Jest52 suites/733개, typecheck, server:check, canonical8파일, Chromium golden3개 통과. 규칙은 `nyang-v1-a0542434d2300583`, 서버 복사본·버전·합법적 입력 fixture 재생성했다. 초기 단위검사에는 병렬 빌드 중5초 테스트 timeout이 발생해 빌드 종료 뒤 testTimeout30000으로 재실행했고 단언은 유지했다. xorshift 작은 연속 seed는 첫 후보에 몰려 테스트 입력을 분산했다. 실제 SVG transform은 float32라서0.000024px 차이가 나, 브라우저만 소수3자리 허용으로 검사했다. 존재하지 않던60m fixture버튼도 추가했다. 과거90초 시간 단언은 새 가속 곡선에 맞춰 갱신했다.

사무실 브라우저1개 통과,51/60/100/250 합성 장면을 캡처하고51/60/100을 육안 확인했다. 실제 플레이·실기기/FPS 검증과 구별한다. 최신 빌드의 게임8개 중ESC/터치/숨김 등7개 통과. 광고 첫 실행1개는 ‘잠시 쉬는 중’이 떠 실패했으며 단독 재검은 통과했다. 기존 광고100ms 지연 보호가 발동 가능한 환경임을 남기고, 보호를 제거하거나 전체무실패로 기록하지 않는다.

## 점수 보정 및 다음 작업
사용자 지시로 오똥비의 확인된 공개ID 한 행만82→131로 보정했다. DB조회 및 공개HTTP200에서131·3위 확인. `96601fa`/store/score-correction-2026-10-30.json에 사유를 남겼다. 이는131 입력 replay를 검증했다는 뜻이 아니다. 광고 부활 자동 랭킹은 T02 별도 구현이며 사용자는 기존 기록과 같은 순위표에 합산을 선택했다. 현재 새 난이도는 운영 서버/웹에 배포하지 않았다.
