# 위험 효과음만 제거하기

## 변경 이유와 핵심
사용자는 진동보다 효과음을 끌 때 체감 개선이 크다고 보고했고, 위험 효과음 제거를 선택했다. 다만 특정 소리가 프레임 저하의 유일한 원인이라고 측정된 것은 아니다.

- `App.tsx`: 효과 이벤트를 소리와 진동에 각각 분배한다. `wobble → playHaptic`, `footstep/coffee/fall → audio.cue`이며 coffee/fall 진동도 유지한다.
- `audioCore.ts`: `AudioCue = 'footstep' | 'fall' | 'coffee'`로 좁혀 잘못된 위험 소리 호출을 타입 검사로 잡는다.
- `audio.ts`와 `audio.web.ts`: 위험 플레이어의 생성과 로딩을 제거했다. 전체 플레이어는 배경음 포함 5개에서 4개다. 볼륨만 0으로 하면 불필요한 재생/seek 요청은 남는다.
- 엔진 위험 이벤트와 위험 진동 설정, 표현, 난이도, 랭킹 검증 규칙은 변경하지 않았다. 기존 비동기 재생 취소와 중복 pause 방지도 유지한다.

## 테스트에서 배운 점
App 통합 테스트를 먼저 추가했더니 기존 코드가 여전히 `wobble`을 오디오에 전달해 1개 실패했다. 전달 경로를 분리한 후 같은 테스트가 통과했다. 다른 소리 3개와 진동 3개의 정확한 호출 목록도 함께 검사한다.
플레이어를 하나 삭제하면 인덱스가 밀린다. 기존 fall/coffee 테스트가 엉뚱한 플레이어를 가리키지 않도록 수정하고, 웹/네이티브가 각각 4개만 생성하는지 검증했다.

## 검증 결과
관련 테스트 25개, 전체 Jest 45개 스위트/676개 테스트, TypeScript 검사, ranked:check 8개 파일, 릴리스 준비 테스트 7개, diff --check 모두 통과했다. 규칙 버전은 `nyang-v1-bc732af6f2a7ea66`로 동일하다. 실제 iPhone FPS는 아직 측정하지 않았다.

## 주의 / 다음 연습
원본 `assets/audio/wobble.wav`는 보존하지만 런타임에서 참조하지 않는다. 이미 설치된 TestFlight와 공식 웹사이트는 소스 수정만으로 바뀌지 않는다. 업데이트 후 효과음을 켠 상태로 위험 구간을 지나 소리는 없고 진동은 설정대로 유지되는지 확인한다. 앞뒤 구간 발소리·커피·게임오버 소리도 확인한다.

1. 왜 엔진 wobble을 지우지 않았나? 소리 외의 진동에 쓰이며 이번 요청은 게임 규칙 변경이 아니기 때문이다.
2. 왜 음소거 대신 플레이어를 제거했나? 불필요한 자원과 재생 요청 자체를 없애기 위해서다.
3. 테스트 통과는 실제 성능 향상의 증거인가? 기능 회귀를 확인한 것이며 실제 기기에서 비교해야 한다.

요청 밖 새 결함 발견: 특이사항 없음. 원래 진행 중이던 배포/실기기 검증은 별개로 남아 있다.
