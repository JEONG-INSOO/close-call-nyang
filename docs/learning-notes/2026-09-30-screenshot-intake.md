# 실제 캡처와 App Store 제출 이미지를 구분하기

## 무엇을, 왜

사용자가 실제 플레이 JPG6장을 제공했다. 홈·걷기·일시정지·카운트다운·랭킹·캐릭터 선택이 확인된다. 먼저 파일을 읽기 전용으로 검사하고 Apple 공식 제출 규격과 비교했다. 원본은 수정·삭제하지 않았다.

```powershell
$img = [System.Drawing.Image]::FromFile($path)
try { "$($img.Width)x$($img.Height)" } finally { $img.Dispose() }
```

결과는6장 모두1280×590. Apple6.9인치 가로 제출 규격에는2868×1320/2796×1290/2736×1260이 포함된다. 파일을 크게 늘릴 수는 있지만 원본 화질이 복구되지는 않는다. 전송 중 축소된 것일 수 있어 원본PNG를 먼저 요청한다. 현재 JPG의 확대 시안을 원하면 원본과 파생 결과를 구분하고 화질 한계를 기록해야 한다.

## 알아야 할 점

- 실기기 캡처 수신과 기기QA 전체 통과는 다르다. 이미지에 기종·iOS·빌드번호가 없으며 입력·프레임·오프라인·삭제·Safari복귀는 정지사진으로 증명할 수 없다.
- Apple은 실제 사용 화면을 요구하며 캡처에 가상 계정 정보를 쓰도록 안내한다. 타인으로 보이는 닉네임이 있는4번은 확인 전 공개후보에서 제외한다. 운영 데이터를 바꾸거나 삭제하지 않는다.
- 사진에 없는 커피·사무실·해금 장면을 AI로 그려 실제 앱 캡처처럼 제출하지 않는다. 장식과 캡처의 픽셀 변경은 별개로 판단한다.
- 이번 검사는 파일 치수와 제공된 사진의 관찰이다. 새 이미지 제작·스토어 업로드·심사 제출을 하지 않았고 T02도 완료하지 않았다.

## 요청 밖 발견

store/release-inputs.json은 과거 null 입력 상태이고 review-notes.md에는 옛 닉네임 변경 경로/미게시 URL 설명이 남았다. 현재 확정 결정·소스와 대조해 스토어 자료 Task에서 정리해야 한다. 이미 승인된 공개 이메일·가격·지역을 다시 묻지 않는다. 이 캡처 검사에서 무관하게 수정하거나 심사 완료라고 처리하지 않았다.
