# 첫 닉네임 안내: 한 번의 선택과 다음 도전

## 왜 만들었나
닉네임과 온라인 랭킹 기능은 이미 있었지만, 처음 들어온 사용자는 이를 발견하기 어려웠다. 홈에서 닉네임 설정을 권하고 건너뛰기를 허용한다. 결과 화면은 등록 전 기록을 소급 등록할 수 없다는 사실을 함께 알린다.

## 데이터 흐름
`useOnlineProfile`이 기존 프로필 조회를 마쳐 **guest**라고 확인하면, `useNicknameOnboarding`의 로컬 이력을 읽은 뒤 홈에서 안내를 한 번 연다. `설정하기`는 기존 닉네임 편집기로 이동하고, `나중에`와 닫기는 안내 이력을 저장한다. 두 경우 모두 닉네임을 설정했다고 가정하지 않는다.

저장 키 `close-call-nyang.nickname-onboarding.v1`에는 `{ "schemaVersion": 1, "handled": true }`만 쓴다. 점수·설정·캐릭터 수집이 든 Preferences, 서버 익명 계정, 닉네임 자체는 변경하지 않는다. 온라인 저장을 명시적으로 누르기 전에는 네트워크 쓰기가 발생하지 않는다.

결과 화면은 `guest`일 때 두 문구를 보인다. 서버가 확인한 프로필을 받으면 문구가 사라진다. 방금 플레이한 로컬 결과를 `submitted`로 바꾸지는 않는다. 다음 게임 시작부터 기존 `useRankedGame.start`가 서버 도전을 받을 수 있다.

## 중요한 구분
- `profile === null`은 아직 응답을 기다리는 상태일 수도 있다. 로딩·오프라인·설정 안 됨을 구분하는 상태값을 함께 확인한다.
- 앱에서 안내를 한 번 보여준 상태와 닉네임 저장 성공은 다르다. 닉네임 저장이 실패하거나 편집기를 닫아도 게임을 시작할 수 있고, 결과 안내는 계속 보인다.
- 로컬 저장 읽기가 실패하면 자동 안내를 띄우지 않아 기존 이용자를 신규로 오해하지 않는다. 쓰기가 실패하면 이번 실행에서는 다시 띄우지 않지만 앱 재실행 후 재등장할 수 있다.
- 로컬 이력 로드가 늦게 끝나도 사용자가 게임을 이미 시작했다면 플레이 위에 팝업이 끼어들지 않는다. 로딩 중 누른 선택을 나중에 온 응답이 취소할 수 없도록 메모리 상태를 먼저 갱신한다.

## 검증과 실패에서 배운 점
관련 테스트는 첫 표시/건너뛰기·재실행/기존 사용자/오프라인/저장 실패/지연 응답/결과 화면 문구/저장 후 소멸을 검증했다. 첫 작성 때 두 문구가 든 부모 View를 단일 텍스트로 비교해서 테스트가 실패했다. 각 Text 요소를 따로 조회해 사용자에게 실제로 표시되는 두 줄을 확인하도록 바꿨다.

관련5개 스위트/38개 테스트, 전체Jest48개 스위트/686개 테스트, TypeScript 검사, ranked:check 8개 파일, release 7개 테스트, diff --check 통과. 랭킹 규칙 버전은 `nyang-v1-bc732af6f2a7ea66`으로 유지됐다. 이 검증만으로 iPhone 가로 모드의 실제 키보드 배치나 설치된 TestFlight 동작을 확인했다고 볼 수 없다.

## 다음에 직접 확인해 보기
1. 안내 이력과 닉네임 유무를 왜 별도로 저장했을까? 건너뛰어도 닉네임은 여전히 없고, 기존 프로필은 안내 이력이 없어도 있을 수 있다.
2. 늦은 저장 응답이 화면을 되돌리지 않게 하려면? 선택을 먼저 메모리에 기록하고 응답이 최신인지 확인한다.
3. 왜 결과에서 “다음 도전부터”라고 말할까? 서버는 시작 시 발급한 도전과 입력 증명으로 기록을 검증하므로, 이전 로컬 기록은 소급 등록할 수 없다.

실제 iPhone에서는 가로 키보드 열기/닫기, `나중에` 후 앱 재실행, 결과 화면에서 닉네임 설정 후 새 도전의 랭킹 반영을 확인한다.
