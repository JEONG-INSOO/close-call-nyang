# 승인 시안을 게임 캐릭터로 구현하기

2026-09-22 · 회색 태비 신입사원

## 이번에 바꾼 것

사용자가 승인한 [생성 이미지](../art/grey-tabby-approved-v1.png)를 기본 캐릭터 `rookie`의 새 기준으로 삼았다. 큰 밝은 눈, 웃는 입, 회색 줄무늬, 짧은 팔다리, 맨발 젤리, 정장 재킷·셔츠·파란 넥타이·목걸이형 사원증을 반영했다. 사원증 안에는 작은 고양이 사진과 `ID: 001`이 있다.

세 종 전체 변경 여부에는 별도 선택이 없었으므로, 프롬프트의 신입에 대응하는 **기본 캐릭터만 먼저 적용**한다고 구현 전에 알렸다. `diligent`와 `veteran`의 그림, 0/1/10회 해금, 선택·저장 데이터는 유지했다. 사용자가 고른 것은 생성 시안이며, SVG 구현·범위 제한·게임 규칙 보존은 코드 구조를 확인한 뒤 정한 구현 방법이다.

기존 `grill-me` 확인 흐름에 이어 승인 내용을 decisions에 저장하고, `memory-plan`으로 외형과 포즈를 한 Task에 묶었다. `memory-execute`로 코드·검증·커밋까지 수행한다. 이번에는 PNG 자체를 게임 화면에 붙이지 않고 **시안을 게임용 SVG로 재구성**했다. 따라서 생성 이미지와 픽셀 단위로 동일하지는 않지만, 팔다리를 독립적으로 움직이고 화면 크기에 맞게 선명하게 그릴 수 있다.

## 핵심 코드와 이유

### 그림 부품과 움직임을 분리

`src/scene/GreyTabbyParts.tsx`는 얼굴·머리·정장·팔·꼬리·물병·메모 소품을 그리는 정적 부품이다. 시계나 점수, 엔진에 접근하지 않는다. 회색털/줄무늬/정장 색도 별도 팔레트로 두어 보상 캐릭터의 크림색을 바꾸지 않는다.

`src/scene/NyangCharacter.tsx`는 기존 회전 기준점과 애니메이션을 재사용한다.

```tsx
const rookie = characterId === 'rookie';
const artPose = rookie ? pose : 'game';
const fur = rookie ? GREY_TABBY_COLORS.fur : NYANG_COLORS.fur;
```

발밑 `(0,0)` 기준의 실제 기울기, 거리 기반 발걸음, 실패 뒤 82도 넘어짐은 그대로다. 새 어깨 움직임도 게임의 `distanceM`에서 계산한다. 일시정지로 거리가 멈추면 팔도 멈추며, 별도의 타이머를 두지 않는다.

### 포즈와 게임 상태를 혼동하지 않기

```ts
type EmployeePose = 'game' | 'walk' | 'water' | 'run' | 'notes';
```

이 값은 그림에만 전달하는 선택값이다. `SceneFrame`이나 저장 스키마에 필드를 추가하지 않았다. 실제 앱은 기본값 `game`을 사용하고, 커피 노출은 여전히 `hasCoffee`를 따른다.

```ts
opacity: artPose === 'game' && frame.value.hasCoffee ? 1 : 0
```

`EmployeeCharacterSheet.tsx`는 동일한 `NyangCharacter`를 네 번 그려 걷기·물병·달리기·메모를 보여준다. 물병과 메모는 이 명시적 시트 포즈에서만 나오고, 달리기 포즈는 점수 가속 기능이 아니다. 보상 캐릭터에 시트 포즈를 잘못 전달해도 기존 게임 모드로 처리한다.

게임의 15% 커피, 51% 사무실, 약90초 100%, 난이도, 65도 실패, 동시 터치 상쇄는 수정하지 않았다. 원본·서버 생성 사본·골든 규칙은 `nyang-v1-f7245064c9459310`으로 유지된다.

## 시행착오와 검증

- 첫 집중 검사에서 `strideFor`가 아직 초기화되지 않은 `walkPhaseAt`를 worklet에 담아 `walkPhaseAt is not a function`이 발생했다(57실패/8통과). Worklet은 애니메이션 실행 환경에 함수와 주변 값을 전달하는 방식이라 일반 함수의 선언 끌어올림만 가정하면 안 된다. 의존 함수 다음에 정의하도록 옮긴 후 65개 집중 검사 통과.
- 타입 검사에서 테스트의 `hasCoffee: true`가 변경 가능한 boolean이 아닌 literal `true`로 추론됐다. `makeMutable<SceneFrame>`으로 실제 입력 계약을 명시해 수정했다. 앱 타입을 느슨하게 만들지 않았다.
- 첫 브라우저 검사에서는 달리기 시트 포즈의 회전된 전체 경계와 선 여유가 촬영 영역을 벗어나 두 검사가 실패했다. 시트 viewBox만 `-130 -220 260 250`으로 넓혔다. 게임 크기나 기울기를 줄이거나 검사를 삭제하지 않았다.
- 실제 PNG에서 메모 시 기존 왼손과 연필 쥔 손이 중복돼 보이는 것을 발견했다. 메모 전용 소매/손 조합으로 바꾸고 연필 끝을 메모지에 맞췄다. 테스트만 통과한다고 그림까지 올바르다는 뜻은 아니다.

최종 검증: TypeScript 통과, Jest 43 suites /648 tests 통과(41.01초), ranked:check 및 generator --check 일치, 실제 웹·합성 시트·모의 온라인 빌드 성공, 공개 설정 검사 local-only 통과. 전체 브라우저는 **34통과 /11의도된 중복 제외 /0실패 /0flaky,202.046초**다. 키보드·동시 터치·정지·재시작·저장·잠금·모의 온라인 흐름을 포함한다.

[실제 SVG 네 포즈 시트](../art/grey-tabby-implemented-sheet-v1.png)는 브라우저 캡처다. 생성 이미지가 아니며 실제 게임과 같은 부품으로 그렸다. 54개 기존 포즈를 두 휴대폰 크기에서 검사했고 새 시트의 네 포즈도 경계·소품·ID로 검사했다. 육안으로 최종 시트, 실제844×390/667×375 게임, 667px 화면의 기본/보상3종 미리보기, 커피를 든60도/82도 포즈를 확인했다. 귀·수염·꼬리·컵이 잘리지 않고 메모 손 중복도 해결됐다.

4173 서버의 HTML/JS를 `dist` 파일과 바이트 비교해 일치함을 확인했다. 번들은 `index-884dc65842fe053f113518f8fe99ec14.js`, SHA256 `4afb671e90f65df298983fa2a58b499088a555ee15e7aae96695dce20a5d9ed5`다. 원래 서버를 종료하거나 다시 띄우지 않았다. 게임/카탈로그/저장/물리 서버 사본의 diff는 없고 규칙 해시도 유지된다.

## 알아야 할 점

- 사원증은 실제 작은 화면에서는 '사원증 모양'으로 읽힌다. 사진과 정확한 ID 텍스트는 확대 시트로 확인할 수 있지만, 높이104px인 선택 미리보기에서도 작은 글자를 선명하게 읽을 수 있다고 보장하지 않는다.
- 승인 PNG는 디자인 참고 파일이며 게임의 배포 번들에는 포함하지 않는다. 시트 캡처는 생성 이미지가 아니라 실제 SVG를 브라우저에서 그린 결과로 구별해 보관한다.
- 새로운 판에서 `SharedValue`(화면에 전달하는 변경 가능한 값 묶음)가 교체되므로 새 팔 애니메이션도 `[frame, artPose]`를 구독한다. 이전 판의 값을 계속 읽는 문제가 없는지 검사했다.
- 기존 사용자 4173 서버와 로컬 저장, 다른 미커밋 작업을 보존한다. Playwright는 격리된 브라우저에서 실행한다. 일반 배포물은 여전히 온라인 랭킹 설정이 없는 local-only다.
- iPhone/Expo Go/Hermes, 실제 터치 손맛과 장시간 성능은 이번 Windows 브라우저 검사로 대체할 수 없다. 서버/API/DB 변경이 없어 이번에 원격 재배포나 Deno API 검사를 새로 수행하지 않았다.

## 요청 밖에 남겨 둔 사항

- 기존 랭킹 서버 작업 P02-T03은 여전히 미완료다. 원격 staging의 규칙은 현재 로컬과 다르므로 향후 연결 전에 배포·검증이 필요하다. 캐릭터 요청만으로 이를 완료하거나 production/Pages/스토어에 배포하지 않는다.
- 기존 공용 아트 문서에는 이전 체형 설명도 보관돼 있으므로 최신 항목과 이 노트를 우선 읽어야 한다. 사용자 변경이 섞인 공유 문서 전체를 이번 소스 커밋에 넣지 않는다.
