# iOS 출시 소스를 고정하는 방법

## 무엇을 바꿨나, 왜 필요한가

성실한 냥대리의 승인된 걷기 네 장은 `1 → 2 → 4 → 3` 순서다. 위험·넘어짐을 더한 여섯 장을 `walk-atlas-v4.png` 한 파일에 넣고 380px 간격으로 이동해 한 칸만 보여준다. `DiligentSprite`는 게임의 거리·기울기·넘어짐을 읽고 그림만 바꾼다. 점수/물리는 그대로이므로 서버가 게임을 재생하는 규칙도 변하지 않는다.

홈 화면은 저장한 캐릭터를 즉시 보여주고, 플레이 중에는 그 판이 시작할 때 고른 캐릭터를 유지한다.

```tsx
characterId={screen === 'title'
  ? preferences.value.collection.selectedCharacter
  : runCharacter}
```

테스트 편의를 위한 전체 캐릭터 선택은 `__DEV__`와 로컬 플래그를 동시에 검사한다. 릴리스 실행에서 플래그가 `true`여도 기본 해금 규칙으로 돌아가는 회귀 검사를 추가했다. 실제 달성 횟수를 올리지 않기 때문에 테스트가 저장된 보상 진행을 바꾸지 않는다.

## 실패를 통해 배운 점

브라우저 검사 최초 실행에서 5개 중 4개가 실패했다. 베테랑을 이전 SVG 부품으로 찾던 검사, 제거된 위험 효과음을 여전히 다섯 번째 파일로 기대하던 검사, 숨긴 아틀라스의 전체 너비를 재던 검사가 원인이었다. 실제 렌더러는 아틀라스인데 테스트가 옛 구현의 세부사항을 전제로 했던 것이다.

SVG `getBBox()`는 화면에서 클립으로 숨긴 칸까지 계산할 수 있다. 이제 아틀라스 캐릭터는 380×425의 고유 clipPath와 실제 슬롯 이동, 작은 두 가로 크기의 캡처를 검사한다. 기본 캐릭터는 기존 기하학적 경계 검사를 유지한다. 클립 검사만으로 자연스러운 걷기나 iPhone FPS가 증명되는 것은 아니므로 실기기 QA가 남는다.

테스트용 SVG 요소 타입을 일반 HTML 요소로 처리한 탓에 TypeScript 검사도 한 번 실패했다. `SVGGraphicsElement` 타입과 명시적인 `null` 분기를 적용해 브라우저 DOM 타입을 정확히 맞췄다.

## 소스에서 앱까지의 흐름

승인 PNG 원본 → 생성 스크립트 → 아틀라스 → 앱 소스 커밋 → EAS 업로드 아카이브 → 서명 빌드 → TestFlight 업로드 → Apple 처리 → 실제 iPhone 검사.

이전 1.0.0(5)에는 당시 커밋되지 않은 변경도 들어갔다. Git 해시만으로 그 바이너리를 재현할 수 없었던 이유다. 이번에는 필요한 원본·생성기·런타임·검사를 선택해서 커밋하고, EAS `build:inspect --stage archive`로 업로드 입력 파일의 SHA-256을 대조한다. `.easignore`는 로컬 문서/테스트/설정/미사용 개별 포즈를 업로드에서 제외하고 게임에 필요한 아틀라스를 남긴다.

## 검증과 한계

- 승인 원본 여섯 장에서 2280×425 아틀라스 재생성 검사 통과.
- 타입·아이콘·release 설정·랭킹 규칙 검사 통과. 규칙 버전 `nyang-v1-bc732af6f2a7ea66` 불변.
- 최신 웹은 기존 `dist`를 보존하고 `output/ui-web`에 생성했다. iOS Hermes 번들은 `output/release-preflight-ios` export 성공, 두 보상 캐릭터가 각각 단일 아틀라스로 포함되었다.
- EAS 실제 업로드 검사 사본은 111개 파일이며 로컬 원본과 바이트 불일치 0개. 공개 템플릿 `.env.example` 외 실제 환경/인증 파일은 없다.
- 전체 단위 691/691(49 suites, 40.188s), 브라우저 5/5(50.1s), 두 명령 exit 0. 최종 결과와 검사 출력 위치는 Task의 Validation Results에 기록했다.
- 새 IPA 빌드/업로드, 실제 iPhone 캡처/FPS, Apple 처리/공개 심사는 아직 이 사전 검사의 결과가 아니다. 기존 베테랑 T03와 iOS T03는 기기 증거를 받을 때까지 진행 중으로 남긴다.

## 다음 연습

1. `__DEV__` 검사를 제거하면 배포판의 캐릭터 선택에 어떤 문제가 생기는지 설명해 보기.
2. clipPath로 한 칸을 숨겨도 `getBBox()`가 커지는 이유를 설명해 보기.
3. EAS 빌드가 성공했어도 iPhone 테스트와 Apple 처리 결과를 따로 확인해야 하는 이유를 말해 보기.

범위 밖 발견: 중단된 npx 캐시의 모듈 누락과 Windows 테스트 서버 종료 대기가 있었다. 임시 EAS 도구를 별도 `output`에 설치하고, 테스트 서버를 작업 세션에서 관리해 검사를 재개했다. 프로젝트 의존성을 강제 업데이트하지 않았다.
