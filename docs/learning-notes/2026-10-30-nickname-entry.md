# 첫 화면에서 닉네임 입력을 한 번 안내하기

## 무엇을 왜 바꿨나

이전에는 안내 창에서 설정 버튼을 눌러야 입력창이 열렸다. 이제 닉네임 없는 사용자가 홈에 처음 들어오면 입력칸을 바로 보여준다. `App.tsx`의 진입 조건을 통과하면 다음 두 작업을 한다.

```ts
onboarding.markHandled();
changePanel('nickname');
```

표시했다는 사실과 닉네임 저장은 다른 상태다. 표식만 저장해도 닫은 뒤 다시 실행할 때 창이 반복되지 않는다. 실제 익명 계정 생성과 닉네임 등록은 사용자가 저장 버튼을 누를 때 시작한다. 닫기 후에는 가입 없이 게임할 수 있고, 나중에 설정 화면에서 첫 닉네임을 등록할 수 있다.

## 기존 사용자와 데이터

`nicknameOnboarding.ts`의 저장 키만 v2로 올렸다. 기록 내부의 schemaVersion은 여전히1이다. 이전 v1 안내를 넘겼던 손님에게 실제 입력칸을 한 번 더 제시하기 위한 변경이다. v1 표식, 최고기록, 캐릭터, 서버 프로필은 지우지 않는다. 이미 닉네임이 있는 사용자는 v2를 처리한 것으로 기록하고 창을 열지 않는다.

프로필 확인 중, 삭제 중, 화면 세로 상태, 게임 진행 중, 다른 창이 열린 상태에는 끼어들지 않는다. 저장소를 읽지 못했다면 읽지 못한 데이터를 덮거나 반복 안내하지 않고 수동 설정 경로를 유지한다. 서버 연결이 구성되지 않은 로컬 빌드에도 가입을 강요하지 않는다.

## 데이터 흐름

로컬 표식 읽기 → 프로필 상태 확인 → 홈과 가로 화면 조건 확인 → 입력창 표시와 표식 저장 → 사용자가 저장 → 닉네임 검증과 서버 등록 → 다음 도전부터 서버가 발급한 판으로 랭킹 참여.

표식을 서버 계정으로 간주하면 안 된다. 닉네임만 다시 입력해 다른 기기나 삭제한 익명 계정을 복구할 수 있는 것도 아니다.

## 검증

전체 Jest52 suites/738개와 typecheck가 통과했다. 단위 테스트는 처음 표시·기존 v1 표식 유지·기존 프로필 예외·수동 설정·읽기 실패를 확인한다. 최신 main/online 빌드를 각각 생성했고 static web 검사도 통과했다. 브라우저는3가지 화면 크기의 닉네임 흐름과 모의 API 온라인3흐름이6pass/6의도적skip이다. small-landscape 캡처에서 입력칸·닫기·스크롤 영역을 육안 확인했다.

격리된 브라우저 검사는 실제 입력칸 표시와 닫기·재실행·플레이 가능, 저장하기 전 익명 가입 요청이 없음을 확인한다. 온라인 회귀에는 광고 부활 후 두 번째 입력 proof 제출도 포함한다. 모의 API 검사는 실제 운영 가입 성공의 증거와 구별한다. 첫 static 검증 명령은 인자 형식이 틀려 사용법 오류가 났고, 올바른 `--dist` 형식으로 재실행해 통과했다. 아직 새 웹을 공개하거나 iPhone 앱을 갱신하지 않았다.

## 알아야 할 점과 복습

브라우저 localStorage와 iPhone AsyncStorage의 사용은 동일한 서비스 경계를 통하지만 실제 기기에서 키보드와 가로 화면 레이아웃 확인은 별도다. 이전 `NicknameWelcomePanel` 컴포넌트는 더 이상 App에서 사용하지 않으며 별도 정리 대상으로 남겼다. 이번 기능과 무관한 사용자 아트 수정은 커밋하지 않는다. 추가 기능 결함은 발견되지 않았다.
