# 베테랑 냥대리: 승인한 네 장으로 걷기 아틀라스 만들기

사용자가 선택한 `tabby-walk-frame-01.png`부터 `04.png`까지를 숫자 순서대로 `docs/art/source/veteran-mentor/frame-1.png`부터 `frame-4.png`에 원본 바이트 그대로 보존했다. 복사 전후 SHA-256이 같고, 각 그림은 1186×1326의 투명 RGBA다. 위험·넘어짐 두 장을 더해 여섯 장짜리 원본 세트를 만들었다.

게임은 큰 원본 여섯 개를 매번 따로 그리지 않고 `scripts/build-veteran-frames.mjs`로 만든 2280×425 아틀라스의 한 칸을 보여주게 될 예정이다. 빌더는 각 그림의 보이는 픽셀 중 가장 낮은 위치를 찾아 발 기준선을 맞춘다. 실제 런타임 연결은 다음 작업(T02)이며, 이번 작업에서 게임 물리·점수·해금·배포는 바꾸지 않았다.

```powershell
node scripts/build-veteran-frames.mjs --check
node --test scripts/build-veteran-frames.test.mjs
```

`--check`는 아틀라스를 고치지 않고 원본에서 다시 만든 결과와 비교한다. 검사가 파일을 자동 수정하면 오래된 출력이나 손으로 바뀐 파일을 알아차릴 수 없기 때문이다. 크기·알파·칸 배열은 자동 검사하지만, 자연스러운 걸음은 실제 게임에서 눈으로 확인해야 한다.

중요한 예외: 01과 03에서 모두 화면 오른쪽 발바닥 젤리가 보인다. 이를 설명한 뒤 사용자가 **네 장 그대로 사용**하기로 확정했다. 임의로 이미지를 미러링하거나 반대발을 새로 생성하지 않는다. 걸음의 좌우 교대가 나중에 어색하면 별도 아트 수정 작업으로 다룬다.

복습: 왜 원본 PNG와 게임용 아틀라스를 분리할까? 같은 크기의 이미지라도 발 기준선이 다르면 어떤 일이 생길까? 자동 검사만으로 걸음의 자연스러움을 증명할 수 있을까?
