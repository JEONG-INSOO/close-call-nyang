# 아슬아슬 냥대리 아트 디렉션

## 구현 범위와 확인 상태

P01-T03은 SVG 벡터 장면과 표시 전용 애니메이션을 만드는 작업이다. 외부 캐릭터 이미지나 다운로드한 그림을 넣지 않고 `react-native-svg`의 Path, G, Circle, Ellipse, Rect 등으로 작성했다. 게임 화면 연결·캐릭터 선택·해금 저장은 아직 이 작업의 범위가 아니다.

아래 설명은 실제 소스의 구조와 수치에 대한 기록이다. 브라우저 실플레이 시각 검사는 T06, iPhone 실기기 검사는 P03에서 수행할 예정이며 **아직 완료한 것으로 간주하지 않는다**. 단위 테스트와 번들 성공은 동작 계약을 확인하지만 두 발이 자연스럽게 보이는지, 작은 화면에서 표정과 커피가 잘 구분되는지까지 증명하지 않는다.

## 비율과 공통 좌표

게임판은 `960 × 540`, 지면은 `y=425`, 캐릭터의 화면상 기준점은 `(270, 425)`이다. 화면 비율이 달라도 게임판 전체를 16:9로 맞춰 여백을 남기며, 임의로 잘라내지 않는다. 거리 1m는 장면상 40px이다.

| 구성 | 설계 높이 | 역할 |
| --- | ---: | --- |
| 전체 | 205 | 머리가 큰 약 1.74등신 실루엣 |
| 귀를 포함한 머리 | 118 | 표정과 좌우 기울기를 읽는 중심 |
| 몸통 | 51 | 정장·셔츠·넥타이·사원증 |
| 다리와 신발 | 36 | 독립적으로 움직이는 두 발 |

이 수치는 기본 리그의 설계 구간이다. 애니메이션 중 발 들기, 꼬리, 외곽선, 보호 표시까지 포함한 모든 프레임의 실제 픽셀 경계가 항상 205px라는 뜻은 아니다.

`NyangCharacter` 안의 공통 `NYANG_RIG`는 다음 위치를 사용한다.

- 발밑 회전 기준점: 로컬 `(0, 0)`. 화면 전체 중심으로 회전하지 않는다.
- 다리 기준: 왼쪽 `x=-19`, 오른쪽 `x=19`; 다리 그룹은 기본 `y=-36`에서 각각 움직인다.
- 커피 컵 기준: 로컬 `(58, -58)`. 세 캐릭터가 같은 컵 그룹·잡는 팔 위치를 공유한다.
- 꼬리 부착 위치: 로컬 `(-30, -48)`. 몸 기울기에 반응하는 시각 동작만 수행한다.

얼굴·넥타이·소매가 달라도 리그, 발밑 기준점, 컵 위치는 동일하다. 이 좌표는 렌더링 값이며 충돌 판정이나 캐릭터별 능력치가 아니다.

## 새로 구성한 냥대리 모습

참고에서 가져오는 것은 큰 머리·작은 몸·짧은 팔다리라는 넓은 비율 방향뿐이다. 구현은 둥글게 꺾은 삼각 귀, 살짝 오른쪽으로 향한 볼과 주둥이, 작은 분홍 코, 짧은 수염, 뒤로 휘어진 꼬리로 구성했다. 눈·눈썹·입의 곡선과 정장의 세부를 직접 작성했고, 특정 참고의 줄무늬나 선원복·모자·상징적인 소품 조합을 재현하지 않는다.

기본 복장은 크림색 털, 남색 재킷, 흰 셔츠, 민트색 넥타이와 작은 사원증이다. 두 다리는 별도 그룹이고 신발 실루엣도 분리한다. 커피는 머리 아래에 가려지지 않도록 앞쪽 손에 둔다. 이 설계 의도는 후속 시각 검사에서 실제로 확인해야 한다. 비율 변경이나 직접 그렸다는 사실만으로 법적·라이선스 적합성이 보장되는 것은 아니다.

| ID / 한국어 이름 | 얼굴 | 복장 차이 | 해금 카탈로그 기준 |
| --- | --- | --- | --- |
| `rookie` / 허둥대는 냥대리 | 둥글고 열린 눈, 올라간 눈썹, 작은 불안한 입 | 조금 삐뚤어진 넥타이 | 기본, 0회 |
| `diligent` / 성실한 냥대리 | 부드러운 눈, 낮아진 눈썹, 작은 피곤한 입과 옅은 눈 밑 선 | 살짝 느슨하지만 정돈된 넥타이 | 100% 달성한 서로 다른 판 1회 |
| `veteran` / 베테랑 냥대리 | 편안한 눈, 한쪽 올라간 눈썹, 비대칭 미소 | 가지런한 넥타이와 접은 소매 | 100% 달성한 서로 다른 판 10회 |

`catalog.ts`는 기준과 표시 순서만 제공한다. 달성 횟수를 올리거나 저장하지 않는다. 모든 외형은 동일한 난이도·물리·실패 판정을 사용하며, 캐릭터 선택은 이후 UI와 저장 작업에서 연결한다.

## 색과 선

공통 색은 [테마 토큰](../src/theme/tokens.ts)을 기준으로 한다.

| 용도 | 색 |
| --- | --- |
| 밝은 바탕 | `#FFF8F0` |
| 하늘·창문 | `#DDEFF7` |
| 라벤더 | `#BEB6E8` |
| 민트 | `#BFE3D1` |
| 복숭아색 | `#FFD5BD` |
| 짙은 외곽선·글자 | `#394352` |
| 크림색 털 | `#F9E4C8` |
| 남색 정장 | `#354A68` |
| 흰 셔츠·종이 | `#FFFFFF` |

일반 외곽선은 약 2~4px, 둥근 선 끝과 연결을 사용한다. 꼬리는 겹친 굵은 선으로 색 면과 테두리를 만든다. 배경 인물은 주인공보다 작고 조용한 형태로 두며, 숫자 UI와 버튼 글자는 이후 RN Text 계층에서 읽기 쉽게 다룬다.

## 출근길에서 사무실로

[StreetScene](../src/scene/StreetScene.tsx)은 파스텔 건물과 창문, 나무, 대중교통 표지 같은 소품, 보도를 고정 개수의 타일로 반복한다. 먼 스카이라인은 960px 타일 2개, 가까운 거리는 640px 타일 3개를 사용하며 서로 다른 속도로 움직인다.

카페는 반복 타일에 넣지 않은 단일 사건이다. `cafeX = 270 + (15 - distanceM) × 40`이므로 15m에서 주인공과 정렬한다. 컵 표시는 거리 계산을 다시 하지 않고 전달받은 `frame.hasCoffee`를 따른다.

회사 문도 실제 거리로 배치한다. `entranceX = 270 + (50.5 - distanceM) × 40`이며 50.5m에서 주인공 기준점과 만난다. 사무실의 `officeBlend`는 50~51m 사이에 0에서 1로 변하지만, 사무실 전체가 갑자기 화면을 덮는 전환은 아니다. `ClipPath`의 오른쪽 노출 영역과 앞에 그린 불투명 문틀을 함께 사용해 문 너머 공간만 드러낸다. 논리상 거리 51m부터 사무실 단계다. 문이 지나가는 순간의 가림과 공간 연결은 반드시 후속 브라우저·기기 검사로 확인한다.

[OfficeScene](../src/scene/OfficeScene.tsx)은 1,200px 타일 2개를 유지한다. 각 타일 안에는 서로 다른 두 배치가 있다.

1. 업무 자리: 창문·게시판·책상·모니터·의자·화분·복사기·서류 더미.
2. 대화 자리: 화이트보드·시계·상사와 동료·추가 책상과 화분.

상사는 열린 손으로 설명하고 동료는 서류를 들고 풀이 죽은 자세를 취한다. 폭력, 위협, 모욕 대사는 없으며 두 인물은 장식이다. 반복 횟수만큼 새 노드를 늘리지 않고 좌표만 나머지 연산으로 이동한다. 긴 거리에서도 배열과 SVG 노드 수는 거리와 무관하다.

## 움직임과 게임 규칙의 경계

- 기울기는 `SceneFrame.angleRad`를 그대로 시각 회전으로 변환한다. 별도 균형 게이지를 만들지 않는다.
- 두 다리는 거리·진행 시간 기반 보폭을 서로 반대로 움직이고 발을 조금 들어 올린다. 멈춤 동안 입력 프레임이 고정되면 걸음과 꼬리도 고정된다.
- 꼬리와 작은 얼굴 이동은 균형 상태를 보조해 읽게 하지만 물리 상태에 힘을 가하지 않는다.
- 실패 후에는 점수와 물리 시간을 변경하지 않는 로컬 애니메이션으로 약 240ms 동안 넘어짐을 마무리한다. 일반 모션에서는 기울어진 방향 쪽 약 82도까지, 모션 감소에서는 즉시 최종 자세를 표시한다.
- 보호 상태는 부드러운 민트색 윤곽으로 표시한다. 번쩍이는 효과는 사용하지 않는다.
- 모션 감소는 장식적인 움직임에 관한 설정이다. 필요한 몸 기울기·다리 정보는 유지하고 판정 기준은 바꾸지 않는다.
- 이 장면에는 100% 축하 효과가 없다. 100%에서 점수 글자색만 바꾸는 규칙은 이후 HUD의 역할이다.
- 장면은 엔진 상태를 쓰거나 게임 액션을 보내지 않는다. 저장소·광고·리더보드 접근도 없다.

## 후속 시각 검사표

다음 조합을 **세 캐릭터 모두** 확인한다. 테스트에서 사용하는 프레임과 실제 플레이 화면을 구분하며, 조합을 렌더링했다는 사실을 실기기 품질 확인으로 기록하지 않는다.

| 거리 | 확인할 장면 |
| ---: | --- |
| 0 | 출근길, 발·꼬리·정장 실루엣 |
| 14.9 | 카페 직전, 정상 플레이에서 커피 없음 |
| 15 | 카페 정렬, 정상 플레이에서 커피가 나타남 |
| 50 | 거리 단계, 문과 사무실 노출 시작 경계 |
| 50.5 | 문이 캐릭터 기준점을 통과, 실내 클립 경계 |
| 51 | 사무실 단계, 전환에 빈 공간·화면 번쩍임이 없는지 |
| 100 | 추가 축하 효과 없음, 캐릭터 외형 유지 |
| 250 | 반복 사무실의 연결·노드 수·소품 가독성 |

각 거리에서 중립과 `angleRad = -0.55 / +0.55`를 비교한다. 커피 없음/있음, 진행/일시정지, `fallen` 전후, 보호 시간 없음/있음, 모션 감소 꺼짐/켜짐도 점검한다. 정상 플레이에서는 15m 이후 커피가 있지만, 렌더링 계약 검사에서는 거리와 무관하게 `hasCoffee`를 바꾼 프레임도 사용해 플래그 전달을 확인할 수 있다.

세 캐릭터의 커피·기울기 검사에서는 특히 다음을 본다.

- 신입: 둥근 눈과 삐뚤어진 넥타이가 작은 화면에서도 구분되는가.
- 성실: 부드러운 눈과 피곤한 표정이 기울기 중에도 신입과 다르게 읽히는가.
- 베테랑: 비대칭 미소와 접은 소매가 컵을 든 자세에도 남는가.
- 공통: 발 두 개와 컵·꼬리가 머리나 문틀에 지속적으로 가려지지 않는가; 회전 기준점과 컵 위치가 변형별로 흔들리지 않는가.

레이아웃은 960×540, 844×390, 1366×768 및 세로 화면으로 확인한다. 세로 화면의 회전 안내와 실제 조작 버튼은 T04에서 연결한다. 10,000m 같은 장거리 프레임에서는 배경 반복 경계와 유한한 변환 값을 확인하되, 수치상 안전함과 자연스러운 시각 품질을 별도로 기록한다.

검사 결과는 수행 후 [학습노트](./learning-notes.md)에 환경·실제 관찰·남은 문제를 남긴다. 현재 이 문서는 시각 검사를 완료했다는 보고서가 아니다.
