### 시간과 실패 처리에서 주의할 점

1. 화면 상태는 title → countdown → playing → result이며 paused/ad 경로가 별도로 있습니다. COUNTDOWN3초와 광고5초에는 거리·게임 시간이 늘지 않습니다. paused는 모든 시계를 멈추고 RESUME을 명시적으로 받아야 돌아옵니다.
2. 기본 계산은 고정1/120초입니다. 한 틱 중간에 사건 예고가 끝나면 그 시점에서 나눠 남은 구간에만 힘을 적용합니다. 보호 시간이 끝나는 틱도 같은 원칙입니다.1.2초 예고 이전에 힘이 미리 생기지 않게 하는 이유입니다.
3. 실패 각도를 넘는 틱은 실제 임계 각도에 도달한 비율만 거리·시간에 반영합니다. 넘어지고 난 뒤의 커피/발걸음을 지급하지 않습니다. 반대로 실패 전에15m를 통과했다면 커피는 정상 획득합니다.
4. 입력은 `(right ? 1 : 0) - (left ? 1 : 0)`이므로 양쪽을 동시에 누르면0입니다. 손가락/키보드 개별 해제와 실제 프레임 누적은 후속 controller 작업입니다.
5. 개발 광고 요청과 완료 양쪽에서 mockAdsEnabled를 검사합니다.5초를 채우면 같은 거리에서 한 번만 부활하고3초 카운트다운 후1.5초 보호됩니다. 보호는 실패 판정의 명시된 예외이며 난이도는 현재 거리 기준으로 유지합니다.

엔진의 라디안을 그림 회전용 각도로 바꿉니다. 몸은 발밑(0,0)을 중심으로 기울고, 양 다리는 반대 방향으로 보행합니다. 그림이 엔진 값을 새로 계산하거나 되쓰지 않습니다.

1. Reanimated SharedValue는 React 화면 전체를 매번 다시 그리지 않고 변환 속성을 갱신하는 공유값입니다. T04 controller가 전달할 프레임을 현재는 명시적 테스트 자료로 검증했습니다.
2. 커피는 `hasCoffee`를 읽으며 거리15를 다시 판정하지 않습니다. 컵의 위치 그룹과 표시/숨김 그룹을 나눠 세 캐릭터 모두 손 위치(58,-58)를 유지합니다.
3. 배경·걸음은 거리·게임 시간에만 의존해 정지 시 멈춥니다. 실패 후240ms 넘어짐 마무리는 로컬 표시 애니메이션일 뿐 점수는 바꾸지 않습니다. 모션 감소에서는 즉시 최종 자세를 표시합니다.
4. 보호 윤곽은 깜빡이지 않습니다. 게이지·100% 축하·캐릭터별 능력치 차이는 없습니다.100% 글자색은 후속 HUD의 역할입니다.
5. App.tsx는 아직 준비 화면입니다. 모듈 구현과 실제 플레이 화면 연결 완료를 구분해야 합니다. 해금 저장·온라인 리더보드도 아직 연결하지 않았습니다.

### 실패와 해결

- 첫 통합 검사2건은 컵 위치 그룹에서 투명도를 찾던 테스트가 표시 그룹과 맞지 않아 실패했습니다. `cup`의 고정 좌표와 `cup-visibility`의 표시 속성을 따로 검사하도록 고쳤습니다.
- 새 판에서 공유값 객체 자체를 교체하는 테스트가 실제 결함을 찾았습니다. 배경 훅의 빈 의존성 배열 때문에 카페가 이전 판의870px 위치에 남았습니다. 해당 배경 변환을 `[frame]`에 의존하게 수정했고, 이전 프레임을 바꿔도 새 장면이 영향을 받지 않음을 확인했습니다.
- 파일 편집 도구의 샌드박스 오류는 승인된 동일 apply_patch 실행 경로로 처리했습니다. 보안 설정이나 사용자 도구는 바꾸지 않았습니다.
- 로컬 프리뷰 번들은 만들었으나 브라우저 도구가 `trusted Node process exited unexpectedly`로 두 번 종료됐습니다. 육안 검사를 성공으로 기록하지 않았고 임시 로컬 서버는 종료했습니다. 프리뷰는 ignored `output/`에만 있으며 배포 앱·커밋에는 넣지 않습니다.
