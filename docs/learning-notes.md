### 시간과 실패 처리에서 주의할 점

1. 화면 상태는 title → countdown → playing → result이며 paused/ad 경로가 별도로 있습니다. COUNTDOWN3초와 광고5초에는 거리·게임 시간이 늘지 않습니다. paused는 모든 시계를 멈추고 RESUME을 명시적으로 받아야 돌아옵니다.

4. 입력은 `(right ? 1 : 0) - (left ? 1 : 0)`이므로 양쪽을 동시에 누르면0입니다. 손가락/키보드 개별 해제와 실제 프레임 누적은 후속 controller 작업입니다.
5. 개발 광고 요청과 완료 양쪽에서 mockAdsEnabled를 검사합니다.5초를 채우면 같은 거리에서 한 번만 부활하고3초 카운트다운 후1.5초 보호됩니다. 보호는 실패 판정의 명시된 예외이며 난이도는 현재 거리 기준으로 유지합니다.

- `shareText.ts`, `share.ts`, `share.web.ts`, `ShareFeedbackPanel.tsx`: 정수 점수와 예정 Pages URL을 동일하게 만들고 iPhone은 공유 시트, 웹은 직접 누른 동작에서 클립보드를 호출합니다. 취소는 조용히 끝내고, 실패하면 선택 가능한 텍스트를 보여줍니다. 이전 판의 늦은 응답은 새 판 위에 표시하지 않습니다. 네이티브 취소와 공유 완료는 [React Native Share](https://reactnative.dev/docs/share)의 action으로 구분합니다.
- `scripts/generate-audio.mjs`, `assets/audio/`: 외부 곡·샘플 없이 코드의 음계/화음/합성파로12초·100BPM·5마디 출근 음악과0.10~0.58초 효과음4개를 생성합니다. 44.1kHz/16-bit/mono WAV의 헤더·샘플 수·비무음·클리핑·루프 경계·실제 파일 바이트를 검사합니다. `package.json`에는 재생성 명령만 추가했고 패키지 의존성은 바꾸지 않았습니다.
- `audio.ts`, `audio.web.ts`, `audioCore.ts`, `haptics.ts`: 네이티브 Expo 플레이어5개/웹 HTML 오디오5개를 재사용합니다. 공통 계층은 설정·사용자 재생 허용·쿨다운·동시 효과음2개·중단·비동기 취소를 다룹니다. 음악 목표 볼륨0.15, 효과음 최대0.4이며 미지원/거절이 게임을 멈추지 않습니다. 진동은 별도 설정이고 웹에서는 요청하지 않습니다.
- `rewardedAds.ts`, `MockAdScreen.tsx`: 영상 대신 가상의 사내 카페 문구와 남은 초를 보여줍니다. 화면은 `adSeconds`를 올림해 표시할 뿐 보상을 주지 않습니다. 기존 엔진이5초의 활성 시간, 취소, 배경 정지, 한 판1회 부활을 판정합니다. production에서는 버튼·요청 함수·엔진 모두 광고를 허용하지 않습니다.
- 테스트/`jest.setup.ts`: 실제 저장 훅·앱·엔진을 사용하되 AsyncStorage의 디스크 경계와 테스트별 오디오/OS 경계만 모의합니다. 네이티브 모듈이 없는 Node 검사가 실제 소리·기기 저장 검증을 대체하지는 않습니다.

### 핵심 코드와 주의할 점

```ts
attempt.counted = true; // await 이전의 동기 중복 방지
if (!session.hydrated) session.completionDelta = Math.min(10, session.completionDelta + 1);
```

첫100% 순간에 이미 처리했다고 표시하므로 같은 판의101/200%·결과·정지·재렌더링이 보상을 반복하지 않습니다. 로딩 중에는 증가분을 따로 기록해 저장된9회 위에 새1회를 정확히 더할 수 있습니다.

1. 저장은 동시에 여러 쓰기를 시작하지 않고, 진행 중1개+최신 대기값1개로 합쳐 순서대로 처리합니다. 늦게 끝난 옛 쓰기가 새 설정·최고 기록을 덮어쓰지 않도록 한 것입니다. 읽기 실패 직후 기본값을 자동으로 덮어쓰지 않으며, 이후 사용자가 만든 변경에서 다시 저장을 시도합니다.
2. 저장 실패 시 메모리 상태는 유지되고 안내가 나타납니다. 쓰기 완료 전에 앱이 강제 종료돼도 안전하다는 보장은 없습니다. 앱/브라우저 데이터 삭제 시 수집과 기록은 사라지며 기기 간 동기화·변조 방지·온라인 순위 검증은 아닙니다. 이 로컬 키에는 사용자 신원·토큰·입력 이력을 넣지 않습니다.
3. ordinary/offline 판은 수집에 포함됩니다. `beginAttempt(!flags.mockAdsEnabled)`로 가상 광고를 켠 개발 판 전체를 제외하며 광고를 실제로 봤는지와 무관합니다. 재개·부활은 새 판이 아니고, 선택 변경도 기존 판의 외형/능력을 바꾸지 않습니다.
4. 설정을 닫아도 멈춘 게임이 자동 진행되지 않습니다. 음악은 활성 플레이에만 재생하고 넘어짐 효과음은 결과 전환 직후 별도로 허용합니다. AudioPlayer·구독·요청을 발걸음마다 새로 만들지 않습니다.
5. 브라우저 클립보드는 [secure context와 완료 Promise](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)를 확인합니다. 성공 전에 복사됐다고 표시하지 않습니다. 공유 문구의 Pages URL은 아직 배포 전 예정 주소입니다.
6. 개발 가상 광고는 `__DEV__`와 `EXPO_PUBLIC_ENABLE_MOCK_AD=true`가 함께 필요합니다. production에서는 환경변수만 바꿔 켤 수 없습니다. 실제 광고 SDK는 설치하지 않았고 광고가 들어온다고 자동 전환되지도 않습니다. 향후 별도 공급자·외부 보상 API·네이티브 검증 작업이 필요합니다.

### 실패·검토와 해결

- 앱 검사에서 Expo Audio의 네이티브 prototype이 없어 초기화가 실패했습니다. 앱 통합 테스트는 오디오 서비스 경계를, 오디오 전용 테스트는 개별 플레이어 경계를 모의해 각각의 책임을 검사합니다. 실제 앱 코드를 가짜 플레이어로 바꾸지는 않았습니다.
- 저장 실패 문구가 실제 화면 트리에는 있는데 접근성 조회에서 숨겨지는 결함을 찾았습니다. 제목/결과/정지의 inline overlay가 `accessibilityViewIsModal`로 형제 안내까지 가리고 있었습니다. 이미 숨겨진 GameScreen의 접근성 경계는 유지하고 불필요한 inline modal 표지만 제거했습니다. 실제 설정·캐릭터·공유 Modal은 유지합니다.
- 설치된 Expo57 웹 플레이어는 `HTMLAudioElement.play()`의 Promise를 반환하지 않아 자동재생 거절을 직접 잡기 어렵습니다. 외부 라이브러리를 패치하거나 전역 오류를 숨기지 않고 별도 웹 어댑터에서 Promise를 처리했습니다. 근거와 [Expo Audio](https://docs.expo.dev/versions/latest/sdk/audio/) 참고는 assets/audio/README.md에 남겼습니다.
- 검토 중 옛 음악 재생 요청이 pause→새 재생 뒤 늦게 실패하면 새 음악까지 멈추는 경합을 재현했습니다. 키별 재생 토큰과 수명 토큰으로 이전 요청의 실패만 무시합니다. 최신 오류는 정상적으로 정지시키고 다음 사용자 동작에서 재시도합니다. 이전 실패/최신 실패를 나눠 테스트했습니다.
