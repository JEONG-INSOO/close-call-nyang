# Decisions: 아슬아슬 냥대리

- Date: 2026-09-21
- Status: Confirmed
- Amendment status: 닉네임·공통 온라인 리더보드, 가입 화면 없음·기기별 플레이어, 닉네임 중복 허용 확정. 2026-09-21 변경 청사진 반영.
- Source: 사용자와 진행한 56개 설계 질문 및 추가 수정. 같은 항목에서는 가장 최근 선택이 우선한다.
- Scope: 인터뷰·계획 후 개발 직전 중단. 모델 변경 안내 후 사용자가 실행을 요청하면 순차 구현한다.

## D01. 게임의 정체성
- **Chosen**: 정식 제목 `아슬아슬 냥대리`. 정장을 입고 두 발로 걷는 귀여운 고양이 직장인. 얼굴·귀·꼬리·두 다리가 분명히 보인다.
- **Rationale**: 직장 생활 코미디와 균형 잡기의 긴장감을 친근한 캐릭터로 표현한다. 이전 인간 김대리와 제목은 폐기한다.

## D02. 참고 범위
- **Chosen**: [Walk the Stork](https://vidkidz.tistory.com/2825)의 오래 걷기·좌우 균형 조작을 참고한다. 원작 코드, 이미지, 소리, 이름을 가져오지 않는다.
- **Rationale**: 냥대리만의 캐릭터, 사무실, 사건, 음악을 제작한다.

## D03. 플랫폼과 개발 환경
- **Chosen**: Windows에서 Expo + TypeScript로 iPhone 및 웹을 개발한다. Mac은 없다. Expo Go로 기기 테스트하고 EAS 클라우드에서 배포용 iOS 앱을 빌드한다. Apple Developer 유료 계정은 이미 보유했다.
- **Rationale**: 하나의 게임 규칙과 화면 코드를 공유하며 로컬 Xcode 없이 개발한다. Expo Go는 테스트 호스트이며 최종 독립 앱 자체가 아니다.

## D04. SDK와 Expo Go 안내 정정
- **Chosen**: Expo SDK 57 안정 패치로 시작하고 정확한 의존성은 lockfile에 고정한다. 사용자는 최신 SDK + EAS 전용 Expo Go 경로를 선택했으나, 최신 사실 확인에 따라 일반 App Store Expo Go를 기본으로 하고 `eas go`를 필요 시 대안으로 남긴다.
- **Rationale**: 앞선 "App Store Expo Go는 SDK 54까지만 지원" 안내는 오래된 문서를 따른 오류였다. [2026-09-03 Expo 공지](https://expo.dev/changelog/expo-go-57-login)는 SDK 57 지원 및 PC CLI와 iPhone 앱의 동일 Expo 계정 로그인을 명시한다. [한국 App Store](https://apps.apple.com/kr/app/expo-go/id982107779)도 버전 57.0.9와 iOS 16.4 이상을 표시한다. 최신 SDK·Expo Go라는 사용자 의도를 유지하며 불필요한 전용 호스트 빌드를 피한다.

## D05. 화면 구성
- **Chosen**: 가로 고정 횡스크롤. 냥대리는 화면 왼쪽 영역에서 오른쪽을 바라보고 걷고, 배경은 왼쪽으로 움직인다. 웹은 가로 게임판을 중앙 정렬한다.
- **Rationale**: 보행과 거리 이동감을 살린다. 이전 세로 화면 결정을 대체한다. 세로 브라우저에서는 회전 안내와 일시정지로 처리한다.

## D06. 조작
- **Chosen**: 양쪽 하단 반투명 좌우 버튼을 누르고 있는 동안 지속 보정. 웹은 좌우 방향키 및 A/D 지원. 좌우 동시 입력은 상쇄한다.
- **Rationale**: 모바일 양손 엄지와 키보드에서 동일한 규칙을 사용한다. 손을 떼거나 앱을 벗어나면 입력을 해제한다.

## D07. 점수
- **Chosen**: 내부 거리 1m = 프로젝트 성공률 1%. 표시값은 내림한 정수. 화면과 공유에는 퍼센트만 표시한다. 100%를 넘어 101%, 102%… 계속 누적한다.
- **Rationale**: 거리와 성공률을 중복 표시하지 않고 기록을 즉시 읽게 한다. 게임상 상한은 없다.

## D08. 난이도와 보행 속도
- **Chosen**: 0~14%는 쉬운 적응 구간. 15%부터 보행 속도와 흔들림이 함께 점진적으로 증가한다. 50% 이후 더 긴장되고 100% 이후에도 상한 없이 완만하게 증가한다.
- **Rationale**: 초반 적응과 장기 기록 경쟁을 함께 제공한다. 가속을 포함해 넘어지지 않고 100%까지 가는 플레이 시간은 약 90초다. 카운트다운·정지·광고 시간은 이 시간에 포함하지 않는다.

## D09. 카페와 커피
- **Chosen**: 15% 지점 카페를 통과할 때 한 손에 커피가 생기며 동시에 가속·난이도 상승이 시작된다. 이후 계속 들고 걷는다.
- **Rationale**: 속도 변화에 시각적 이유를 준다. 이전 30% 획득안은 폐기한다.

## D10. 거리와 사무실
- **Chosen**: 표시 0~50%는 거리 출근길. 50%대에 회사 입구를 통과하고 51%부터 사무실. 일시정지 없는 자연스러운 횡스크롤 전환이다.
- **Rationale**: 사무실에는 책상·복사기·화분·서류 더미 및 상사와 혼나는 직장인 같은 장면을 반복 배치한다. 배경 인물과 소품은 충돌 판정이 없는 장식이다.

## D11. 직장 코미디 사건
- **Chosen**: "긴급 수정!", "팀장님 호출!", "회의 연장!" 등의 문구와 힘의 방향을 미리 예고한 뒤 짧은 좌우 힘을 적용한다.
- **Rationale**: 대응 가능한 사건으로 변화와 소재의 재미를 만든다. 출근길에는 커피/출근 관련 문구로 맞춘다. 예고 방향은 사건의 힘이며 캐릭터 균형 게이지가 아니다.

## D12. 균형과 실패
- **Chosen**: 몸·꼬리·휘청이는 자세를 보고 감각적으로 균형을 잡는다. 균형 게이지는 없다. 위험 각도에 닿는 즉시 실패한다.
- **Rationale**: 엄격한 아케이드 조작을 원한다. 0.4초 유예안은 폐기한다. 정확한 각도와 힘 상수는 청사진의 초기값으로 시작해 플레이 테스트로 조정한다.

## D13. 시작과 결과
- **Chosen**: 별도 튜토리얼 없이 제목 화면의 `업무 시작` → 3초 카운트다운 → 플레이. 결과에서 현재 성공률·최고 기록·재도전·공유를 제공한다.
- **Rationale**: 설명을 읽는 단계 없이 사용자가 준비해서 시작한다. 재도전도 새 판으로 시작한다.

## D14. 개발용 광고와 출시 상태
- **Chosen**: 개발에서만 5초 전체 화면 텍스트 가상 광고. 중도 닫기는 보상 없음. 실제 광고가 준비되기 전 출시 iOS 및 웹에는 광고·부활 진입 버튼이 없다.
- **Rationale**: 부활 흐름을 미리 검증하되 가짜 광고를 사용자에게 출시하지 않는다. 실제 광고 SDK 설치·광고 계정 연동·추적은 이번 구현에서 하지 않는다. 미래 광고 추가에는 네이티브 빌드와 개인정보 설명 재검토가 필요하다.

## D15. 부활
- **Chosen**: 한 판에 1회만 가능. 가상 광고 완료 시 거리와 난이도를 유지하고 몸을 중앙 자세로 복원한다. 3초 카운트다운 및 짧은 보호 시간 후 정상 판정으로 이어진다.
- **Rationale**: 보호 시간만 즉시 실패 규칙의 예외다. 부활 중 시간을 이용해 점수나 광고 보상을 중복 획득할 수 없어야 한다.

## D16. 100% 연출
- **Chosen**: 성공률 숫자의 색상만 바꾼다. 게임 흐름과 배경음악은 그대로 이어진다.
- **Rationale**: 별도 축하 화면·색종이·100% 전용 효과음·100% 전용 진동은 없다. 이전 효과음·진동 제안을 이 결정이 대체한다.

## D17. 일시정지
- **Chosen**: 우측 상단 수동 버튼 및 앱 전환/브라우저 탭 이탈 자동 정지. 돌아와도 사용자가 이어하기를 누르기 전까지 멈춘다.
- **Rationale**: 전화나 앱 전환으로 억울하게 실패하지 않게 한다. 물리·점수·사건·카운트다운·가상 광고 시계와 소리도 함께 멈춘다.

## D18. 비주얼
- **Chosen**: 밝은 파스텔 2D 직장 코미디. React Native SVG로 독창적인 고양이, 거리, 카페, 회사, 배경 인물을 만든다. React Native Reanimated로 보행·기울기·스크롤을 애니메이션화한다.
- **Rationale**: 플랫폼별 선명함과 동작 일관성을 유지한다. 픽셀 아트·실루엣·AI 이미지 대신 코드 기반 벡터를 선택했다.

## D19. 음악·효과음·진동
- **Chosen**: 밝고 자연스럽게 반복되는 낮은 음량의 출근 테마, 발걸음·휘청임·넘어짐 효과음, 지원되는 모바일 진동. 음악/효과음/진동 각각 설정 가능.
- **Rationale**: 긴장감과 코미디를 강화하고 사용자가 개별적으로 끄게 한다. 자체 제작 음원을 사용하고 웹에서는 사용자 입력 후 재생한다.

## D20. 화면 흔들림 줄이기
- **Chosen**: 설정에서 카메라 흔들림과 번쩍임을 줄인다. 필수인 냥대리 기울기와 보행은 유지한다.
- **Rationale**: 이 옵션은 물리·난이도·기록에 영향을 주지 않는다.

## D21. 데이터
- **Chosen**: 사용자 추가 요청으로 닉네임 설정과 iOS/웹 공통 온라인 리더보드를 도입한다. 회원가입 화면 없이 닉네임만 설정하고 기기별 플레이어로 관리한다. 이메일·소셜 로그인과 기기 간 동기화는 제공하지 않는다. 서버에서는 자동 발급한 익명 사용자 ID로 기록 소유자를 식별한다. 기존의 "최고 기록·설정만 저장, 순위표 없음" 결정은 대체된다.
- **Rationale**: 닉네임과 순위로 기록 경쟁을 제공하려는 최신 요청을 반영한다. 기존 분석·오류 전송·광고 추적 제외는 유지한다. 온라인 방식을 선택하면 순위 운영용 데이터 저장은 별도 목적이며 관련 개인정보 설명도 실제 설계에 맞게 갱신한다.

## D22. 공유
- **Chosen**: `아슬아슬 냥대리 프로젝트 성공률 143%!` 형식의 텍스트 공유. iPhone은 시스템 공유창, 웹은 클립보드와 실패 시 수동 복사 안내.
- **Rationale**: 별도 이미지 공유 생성 없이 기록을 전달한다.

## D23. 언어와 앱 구조
- **Chosen**: 한국어 전용. 문구는 한곳에서 관리한다. Router 없이 하나의 앱에서 제목·카운트다운·플레이·일시정지·광고·결과 상태를 전환한다.
- **Rationale**: 작은 게임의 화면과 오디오 수명을 일관되게 관리한다.

## D24. 자동 검증
- **Chosen**: 물리·점수·난이도·부활의 단위 테스트 및 주요 화면/설정 동작 테스트. GitHub Actions의 테스트·타입 검사·웹 빌드가 모두 성공해야 Pages 배포.
- **Rationale**: 규칙 회귀를 방지한다. 자동 테스트만으로 실제 iPhone 조작감·소리·서명·스토어 심사를 검증했다고 간주하지 않는다.

## D25. 웹 배포
- **Chosen**: 일반 정적 웹 게임. PWA·서비스 워커는 제외한다. GitHub Pages 저장소 이름 `close-call-nyang`, 사용자명 `mocca`.
- **Rationale**: 예정 URL은 `https://jeong-insoo.github.io/close-call-nyang/`. 현재 저장소 소유권·공개·배포를 검증한 것은 아니다.

## D26. Git 작업 범위
- **Chosen**: 로컬 Git 저장소 초기화, 작업별 검증·커밋, Actions 설정까지 준비한다. 새 GitHub 저장소 생성과 원격 푸시는 사용자가 수행한다.
- **Rationale**: 선택한 로컬 준비 범위를 따른다. 기존 파일을 보존하고 실제 커밋 작성자 설정이 없다면 실행 시 사용자에게 받는다.

## D27. iOS 식별자와 기기
- **Chosen**: `com.mocca.closecallnyang`. 첫 출시는 iPhone 전용 가로 화면이며 iPad 전용 최적화/스크린샷은 범위 밖이다.
- **Rationale**: 기기 검증 범위를 명확히 한다. 예전 `closecallkim`은 사용하지 않는다.

## D28. App Store
- **Chosen**: 게임/캐주얼, 4세 이상 콘텐츠를 목표로 한다. 실제 등급은 Apple 설문 결과로 확정한다. EAS 빌드 생성, App Store Connect 업로드, 별도 App Review 제출까지 작업 범위에 포함한다.
- **Rationale**: 빌드 업로드와 심사 제출은 다른 단계다. Kids 카테고리 선택을 의미하지 않는다. 심사 통과 보장이나 승인 후 자동 공개는 포함하지 않으며 수동 출시를 준비한다.

## D29. 소개 문구·스크린샷 승인
- **Chosen**: 귀엽고 공감되는 직장인 코미디 문구. 실제 출근길·커피·사무실·결과 화면에 짧은 한국어 홍보 문구를 더한 스크린샷.
- **Rationale**: 스토어 소개 문구와 이미지 및 제출 대상을 심사 제출 전에 반드시 다시 보여주고 확인받는다. 이 확인은 사용자의 명시 요청이다.

## D30. 앱 아이콘
- **Chosen**: 파스텔 배경에 커피를 들고 휘청이는 냥대리 얼굴. 게임의 벡터 디자인과 같은 캐릭터로 제작한다.
- **Rationale**: 작은 아이콘에서도 얼굴과 커피가 보이게 한다. 벡터 원본을 배포 규격 PNG로 출력한다.

## D31. 공개 문서
- **Chosen**: Pages에 지원 페이지와 개인정보처리방침을 함께 배포한다. 제출 때 실제 접근 가능한 절대 URL을 사용한다.
- **Rationale**: 게임 코드가 전송하는 데이터, 기기 내 저장, 사용자가 직접 공유하는 정보, 호스팅 사업자의 요청 처리와 지원 문의를 구분해서 설명한다. 담당자 연락처 등 미확정 운영 정보는 제출 전에 실제 값으로 채운다.

## D32. 학습노트
- **Chosen**: `docs/learning-notes.md` 하나에 세 스킬 설명, 결정 근거, Expo 구조, 물리·시간 처리, 입력, SVG/Reanimated, 저장, 광고 분기, 오디오, 테스트, 배포와 실제 시행착오를 정리한다.

## D33. 개발 직전 중단
- **Chosen**: 결정·계획·청사진을 저장한 뒤 “이제 AI 모델을 변경할 시점입니다”라고 알리고 멈춘다. 사용자가 모델 변경 후 실행을 요청하기 전에는 구현하지 않는다.

## D34. 닉네임·리더보드 변경 요청
- **Chosen**: 추가 질문1에서 가입 없는 닉네임 설정·iOS/웹 공통 온라인 순위표·기기별 플레이어, 질문2에서 닉네임 중복 허용이 확정됐다. 순위표에서 내 기록을 강조한다.
- **Rationale**: 순위표 공유 범위와 사용자 식별은 저장 모델·API·개인정보·출시 검증에 영향을 준다. 이 변경과 관련된 질문만 추가하고 기존 게임 기획은 유지한다.
- **Implementation default**: 기존 최고 기록 방식에 맞춰 플레이어별 역대 최고 성공률로 순위를 구성한다. 기간별 시즌은 추가하지 않는다.
- **Implementation default**: 상위100명과 내 순위, 같은 정수 성공률은 공동 순위(1,1,3). 같은 점수의 표시 순서는 최초 달성 시각·공개ID로 안정적으로 정렬한다. 닉네임이 같아도 익명 ID가 다르면 다른 플레이어다. 이 수치·동률 규칙은 반복 질문을 줄이기 위한 구현 기본값이다.

## D35. 닉네임과 참여 흐름
- **Chosen**: 중복 허용, 기기별 닉네임/기록이라는 사용자 결정을 따른다.
- **Implementation default**: 제목/설정에서 2~12자 닉네임 설정·변경. NFC 정규화 후 한글·영문·숫자·공백을 허용하고 양끝 공백 제거, 연속 공백 축약. 공개 부적절한 이름은 서버에서 거부하고 신고/숨기기 및 운영자 조치를 제공한다. 한 플레이어가 이름을 바꿔도 기록은 같은 행에 남는다.
- **Rationale**: 닉네임은 공개 표시명이며 인증 수단이 아니다. 닉네임 미설정 시 로컬 게임은 가능하고 설정 후부터 온라인 기록에 참여한다. 앱 삭제·브라우저 저장소 삭제·다른 기기에서는 이전 프로필을 복구/동기화하지 않는 한계를 설정 화면에 설명한다. 내 온라인 프로필/기록 삭제를 제공하며 로컬 설정은 유지한다.

## D36. 온라인 구성과 기록 검증
- **Implementation default**: Supabase의 익명 인증·Postgres·Edge Functions로 구현한다. GitHub Pages는 게임 파일을 배포하고, 별도 HTTPS API가 닉네임/랭킹을 처리한다. UI에는 회원가입/로그인 화면이 없다.
- **Rationale**: [익명 인증](https://supabase.com/docs/guides/auth/auth-anonymous)은 이메일/비밀번호 입력 없이 기기별 사용자를 구분한다. 서비스 관리자 키는 서버에만 둔다. 클라이언트는 최고 점수 테이블을 직접 수정할 수 없고 서버가 검증한 기록만 올린다.
- **Implementation default**: 서버에서 판별용 seed와 run ID를 발급하고 고정 tick 입력을 작은 묶음으로 재생해 점수를 계산한다. 최초 정상 넘어짐으로 끝난 판만 랭킹에 반영한다. 개발/가상 부활 판은 production 랭킹에 보내지 않는다. 이는 점수값 조작 방어이며 자동 플레이까지 완전히 막는다는 보장은 아니다.
- **Offline**: 네트워크 없이도 로컬 플레이·기기 최고 기록은 유지. 오프라인에서 시작한 판은 온라인 순위에 소급 등록하지 않는다. 온라인에서 시작한 판의 일시적 전송 실패는 제한된 대기열로 재시도하고, 검증 자료를 잃으면 해당 판만 로컬 기록으로 남긴다.

## D37. 서버 운영과 공개 정보 변경
- **Implementation default**: Supabase Free 범위로 시작하며 실제 계정/프로젝트 연결은 실행 단계에서 한다. 현재 계정 생성·배포·요금제 결제는 하지 않았다. 무료 프로젝트 휴면과 사용량 제한을 운영 문서에 설명하고 유료 전환은 사용자가 결정한다. [요금/제한](https://supabase.com/pricing)
- **Rationale**: 기존 "데이터 전송 없음" 문구는 더 이상 최종 사양이 아니다. 공개 닉네임·검증된 성공률과 비공개 익명ID·인증 세션·검증용 플레이 자료·신고/삭제 처리의 목적 및 보관 기간을 개인정보 페이지와 App Store 답변에 반영한다. 분석·광고 추적은 계속 제외한다.
- **Implementation default**: 현재 규칙 버전의 역대 최고 기록을 유지하고, 검증 중 판은 마지막 요청24시간 후 만료, 중복 응답용 완료 영수증은7일 후 정리, 운영 신고는90일 후 정리한다. 원시 입력은 검증 후 서버에 장기 저장하지 않는다. 최초 출시 이후 물리 규칙을 바꿀 때 랭킹 정책은 별도로 검토한다.

## 코드에서 확인한 사실과 구현 기본값
- 기존 게임 코드·package.json·Git 저장소 없음. README는 메모리 워크플로 스타터 안내이고 `.memory/current.md`는 미설정 예시였다.
- Windows Node `24.19.0`, npm.cmd/npx.cmd `11.17.0`, Git `2.55.0.windows.5` 확인. PowerShell의 npm.ps1은 실행 정책에 막히므로 `.cmd` 명령 사용. 시스템 실행 정책을 변경할 필요 없음.
- Git user.name/user.email 조회값 없음. 커밋 시점에 확인할 운영 정보이며 계정 이름을 임의 작성하지 않는다.
- 각도·초기 속도·이벤트 간격·보호 시간·색상값은 청사진에서 정한 **조정 가능한 구현 기본값**이며 사용자가 수치까지 지정한 것으로 표현하지 않는다.
- 예기치 않은 기존 기능 중복/인접 코드 결함: 특이사항 없음. `.agents`, `.codeburn`, `examples`, 기존 `test` 파일은 게임과 무관하므로 보존한다.
