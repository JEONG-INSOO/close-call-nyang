# Decisions: 첫 닉네임 안내와 결과 화면 참여 안내

- Date: 2026-09-28
- Status: Confirmed
- Scope: 첫 이용 안내 UI와 기기 내 안내 상태 저장. 게임 규칙/서버 랭킹 구조는 변경하지 않는다.

## D01. 첫 안내 시점 — 사용자 선택
- **Chosen**: 닉네임 미설정 사용자에게 첫 실행 홈에서 한 번 “냥대리의 이름을 정해주세요”와 `설정하기 / 나중에`를 표시한다.
- **Rationale**: 첫 플레이 전에 랭킹 참여 방법을 알리되 닉네임 설정을 강제하지 않는다.

## D02. 나중에 선택 — 사용자 선택
- **Chosen**: `나중에` 선택을 기기에 저장하고 이후 자동 안내를 반복하지 않는다. 홈의 기존 닉네임 설정 버튼은 유지한다.
- **Rationale**: 실행할 때마다 게임을 가로막지 않고 사용자가 원할 때 설정할 수 있게 한다. 기기 간 동기화나 앱 데이터 삭제 후 상태 복원은 이번 범위가 아니다.

## D03. 결과 화면 안내 — 사용자 요청
- **Chosen**: 닉네임 미설정일 때 결과 화면에 “닉네임을 설정해 랭킹을 등록해보세요!”를 표시하고 기존 닉네임 설정 버튼으로 연결한다. 별도 강제 팝업은 추가하지 않는다.
- **Rationale**: 첫 안내를 건너뛰어도 플레이 후 자연스럽게 설정 기회를 제공한다. 프로필 설정 성공 후 안내는 숨긴다.

## D04. 랭킹 등록 시점 — 사용자 선택
- **Chosen**: 기존 서버 검증 구조를 유지하며, 결과 안내에 “설정 후 다음 도전부터 랭킹에 참여할 수 있어요”를 함께 표시한다. 닉네임 없이 끝낸 기록은 소급 등록하지 않는다.
- **Rationale**: `src/online/useRankedGame.ts`의 start는 프로필이 없으면 로컬 도전을 시작한다. 서버가 발급한 도전과 입력 증명이 없는 기록을 안내 UI만으로 등록할 수 없다. 오프라인/개발 모드 등 기존 순위 참여 제한도 그대로 유지한다.

## D05. 기존 구현 재사용 — 코드 조사로 확인
- `src/screens/NicknamePanel.tsx`: 기존 입력 검증, 공개 닉네임/익명 식별 안내, 비동기 저장, 오류 표시를 재사용한다. 새 계정 체계나 중복 입력창을 만들지 않는다.
- `src/online/useOnlineProfile.ts`: profile=null은 초기 loading/offline에서도 가능하다. 단순히 null만 보고 기존 사용자를 신규 사용자로 단정하지 않는다. 저장 실패는 설정 성공으로 처리하지 않는다.
- `src/services/preferences.ts`: AsyncStorage 기반 로컬 저장과 로드 실패 시 memoryOnly 처리가 있다. 안내 표시 상태도 기기 내 저장으로 충분하며 DB 변경은 필요 없다. 기존 점수/설정/캐릭터 수집을 초기화하지 않는다.
- `App.tsx`: 홈/게임/패널 상태를 구분한다. 늦은 로드 응답으로 게임 중 안내가 튀어나오거나 다른 패널 위에 겹치지 않도록 한다. 네트워크·저장 실패가 로컬 플레이를 막아서는 안 된다.

## 학습 요약: 왜 이렇게 정했는가
- 안내 화면을 보여줬다는 사실과 닉네임 저장 성공은 서로 다른 상태다. 둘을 분리해야 건너뛰기/저장 실패/재실행을 정확히 처리할 수 있다.
- 사용자에게 보이는 문구도 시스템의 실제 한계와 맞아야 한다. 다음 도전부터 참여한다는 설명으로 방금 기록이 등록된다는 오해를 막는다.
- 계획/구현 단계에서는 최초 실행, 건너뛰고 재실행, 기존 프로필, 저장 성공·실패, 오프라인, 결과 화면 안내 소멸을 검증하고 학습노트에 실제 결과를 남긴다.

## Out of scope
- 보상 캐릭터 2종 그림체 교체, 클라우드 수집 복구, 이전 기록 소급 등록, 광고 활성화, 새로운 TestFlight/웹 배포는 별도 작업이다.
- 닉네임 입력·저장과 결과 화면 버튼은 이미 있으므로 중복 구현하지 않는다. 이번 조사에서 별도의 새 결함은 확정하지 않았다.

## Handoff
- 인터뷰 완료. 다음 단계는 `/memory-plan`으로 파일·타입·조건·테스트 청사진 작성 후 `/memory-execute`로 구현한다.
- 이 결정 문서만 저장했으며 앱 코드·현재 실행 포인터·서버·배포는 변경하지 않았다.
