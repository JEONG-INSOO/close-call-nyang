# Decisions: 긴장감 있는 균형과 평면 찌비 냥대리

- Date: 2026-09-22
- Status: Confirmed
- Stage: grill-me interview complete; planning and implementation not started
- Supersedes: [이전 체형·균형 결정](./2026-09-22-plush-cat-and-balance.md)의 해당 외형/초반 난이도와 [원기획](./2026-09-21-close-call-nyang.md)의 0~14% 쉬운 적응 구간. 그 밖의 저장·해금·조작·배포 경계는 유지한다.

## D01. 사용자 피드백과 이번 범위

- **Chosen (사용자)**: 최신 버전도 너무 쉽고 배경 이동이 느려 루즈하다. 이전 다리 길이 수정만 이어가지 말고 첨부 고양이의 짜리몽땅한 비율·맨발 젤리·굵은 선·평면 벡터 느낌을 더 강하게 반영한다.
- **Rationale**: 직전 코드 검증의 통과는 재미나 미술 만족도의 증거가 아니다. 난이도, 화면 속도감, 캐릭터 조형을 서로 구분해 검증한다.
- **Scope**: 게임 플레이/로컬 시각 피드백을 우선한다. 기존 서버 검증P02-T03은 미완료로 보존하고 이번 변경의 계획 전에 자동 배포를 계속하지 않는다.

## D02. 실제 진행 시간과 배경 이동감

- **Chosen (사용자 선택2)**: 넘어지지 않고100%까지 걸리는 실제 플레이 시간은 약90초를 유지한다. 60초/45초로 압축하지 않는다. 점수 진행은 유지하되 배경 이동감과 균형 난이도를 높인다.
- **Keep (기존 요구/코드에서 확정)**: 거리1m=성공률1%, 15% 카페·커피·전진 가속, 51% 사무실, 100% 이상 무한 진행, 카운트다운/정지 시간의 점수 제외. `speedAt`의 거리 진행 곡선을 화면 배율과 혼동하지 않는다.
- **Implementation default (미측정 시작안)**: 바닥과 가까운 배경의 화면상 속도감을 현재의 약2.5~3배 범위에서 시각 검증한다. 이는 사용자 지정 확정 배수가 아니라 구현 단계의 튜닝 목표다. 먼 배경은 상대적으로 느리게 유지한다. 발걸음 애니메이션과 필요한 발소리 타이밍도 같이 맞춰 미끄러지는 인상을 피하되 점수 속도를 올리지 않는다.
- **Rationale / constraints**: 현재 배경은 거리×40px×층별 이동 비율을 사용한다. 카페/회사 문도 같은 거리 좌표이므로 반복 배경만 바꾸거나 이야깃거리 좌표를 누락하면 커피/사무실 전환과 어긋난다. 화면 속도 변경 후15/50~51%의 정렬·문 클립·반복 타일 빈틈을 함께 확인한다. 모션 감소/일시정지의 기존 의도를 보존하고 화면 흔들기·플래시를 추가하지 않는다.

## D03. 초반 난이도 곡선

- **Chosen (사용자 선택1)**: 플레이 시작 후 첫3초만 적응 → 이후 적극적인 좌우 균형 조작 필요 → 15% 커피부터 추가 난이도 상승.
- **Rationale**: 커피까지 약16초가 걸리는 현재 진행 속도에서도 초반을 길고 쉬운 구간으로 방치하지 않는다. 여기서3초는 시작 전 카운트다운과 별개인 실제 플레이 시간이다.
- **Implementation default**: 첫3초는 부드러운 적응 구간이지 강제 무적·자동 중앙 복귀·실패 유예가 아니다. 이후 힘을 연속적으로 올려 갑작스러운 각도 순간이동이나 정해진 시간 강제 실패를 만들지 않는다. 시작부터의 일반 흔들림을 강화하는 것이며, 커피 이전에 새 경고 사건 시스템을 별도로 추가하지 않는다.
- **Code constraint**: 적응 구간은 `run.elapsedSeconds` 기준으로 정지 중에는 소모되지 않아야 한다. 기존 `protectionSeconds`는 무적과 자동 안정화를 함께 작동시키므로 적응 시간으로 재사용하지 않는다.

## D04. 어려워지는 방법과 공정성

- **Keep (기존 요구)**: 실제±65도 즉시 실패, 화면과 실제 각도 일치, 게이지 없음, 기존 좌우 조작, 양쪽 동시 누름=무입력, 캐릭터별 능력 차이 없음. 임계각을 몰래40도로 되돌리지 않는다.
- **Implementation default**: 입력의 민첩함을 유지하면서 일반 흔들림의 강약/방향 변화를 다양하게 하고, 오래 누르면 반대쪽으로 넘어갈 수 있는 관성을 살린다. 반대 입력을 통한 회복 여지는 남긴다. 단순히 입력을 둔하게 만드는 것을 난이도 상승의 주된 방법으로 쓰지 않는다.
- **Implementation default**: 커피 이후 기존 사건은 더 이르게/자주/분명하게 작용하도록 튜닝한다. 기존1.2초 방향 예고와 사건 비중첩을 유지한다. 첫 대기6→약2초, 종료 후 휴지약4~6초는 가능한 출발 후보이며 최종 수치는 청사진/시뮬레이션/실제 플레이에서 정한다. 초반 긴장감은 일반 균형 변화로 확보한다.
- **Reproducibility**: 불규칙함을 추가해도 같은 시드와 입력이면 같은 결과가 나와야 한다. 프레임별 `Math.random`/벽시계에 기대지 않는다. 고정 시간 간격의 계산과 서버의 입력 재생 검증을 보존한다.
- **Validation intent**: 무입력/한쪽 고정/양쪽 고정뿐 아니라 반복적인 단순 입력 패턴과 적극적인 피드백 입력을 비교한다. 무입력 낙하가 빨라졌다는 사실만으로 난이도가 좋아졌다고 결론 내리지 않는다. 자동 검사는 정합성/회복 가능성/90초 진행을, 실제 사용자 플레이는 재미·난이도 만족도를 확인한다. 목표 생존 시간을 측정 없이 보장하지 않는다.

## D05. 평면 찌비 조형

- **Chosen (사용자)**: 약2등신, 두꺼운 외곽선, 깔끔한 평면 벡터 아트, 귀엽고 짜리몽땅한 고양이. 짧은 팔다리와 맨발 젤리가 특징이다.
- **Chosen (사용자 피드백)**: 현재의 번들거리는 이마 광택·볼 음영과 복잡한 윤곽 표현을 없애고 첨부 이미지의 둥글고 단순한 인상에 가깝게 새로 잡는다.
- **Implementation default**: 큰 둥근 얼굴과 통통한 몸을 함께 설계한다. 머리만 유지한 채 다리만 줄이는 수정은 반복하지 않는다. 약2등신은 전체 높이와 귀 포함 머리 높이의 비율로 검토하되 최종 좌표는 게임 크기에서 정한다. 외곽선은 굵고 일정하게, 내부 선은 최소화하며 단색 면으로 구분한다. 입체 음영/그라디언트/이마 반사광을 넣지 않는다.
- **Implementation default**: 짧은 팔과 둥근 맨발, 발이 들리거나 넘어질 때 보이는 분홍 발바닥 젤리를 그린다. 기존 크림색 계열을 시작 팔레트로 사용하고 원본 로고/얼굴/특정 무늬/의상을 추출하거나 트레이싱하지 않는다. 우리 표정·털무늬·업무 소품으로 구분한다. 이는 법적 안전 판정이나 색상을 사용자가 직접 지정했다는 뜻이 아니다.

## D06. 직장인 복장과 세 캐릭터

- **Chosen (사용자 최종 선택1)**: 넥타이+사원증만 남긴다. 재킷/조끼/셔츠/바지/구두를 입히지 않아 둥근 배와 고양이 실루엣이 잘 보이게 한다.
- **Keep (기존 요구/코드에서 확정)**: 기본2번 rookie, 서로 다른 판의100% 첫 달성 diligent, 10회 veteran. 내부ID/저장키/획득 횟수/자동 장착 없음/다음 판부터 선택 적용은 유지한다. 과거의 ‘정장 유지’는 이번 복장 선택으로 대체한다.
- **Implementation default**: 신입의 허둥댐·성실한 직장인의 피곤함·베테랑의 능청스러움은 단순한 눈/입과 넥타이·사원증 디테일로 구분한다. 기존 얼굴 SVG 좌표를 그대로 남길 의무는 없다. 커피 컵은 새 짧은 앞발과 맞물리게 다시 배치한다. 세 캐릭터는 동일한 물리/공통 체형을 사용한다.

## D07. 실제 게임과 같은 캐릭터 시트 검증

- **Implementation default**: 현재의 SVG 코드 기반 렌더러를 재설계하며 별도의 래스터 그림을 게임에 붙이는 방식으로 바꾸지 않는다. 중립/걷기/커피/큰 기울기/넘어짐을 게임과 같은 SVG로 한눈에 비교할 시트와 실제 휴대폰 크기 캡처를 준비한다. 캐릭터 시트는 QA용이며 출시 앱에 새 메뉴/디버그 경로를 추가하는 뜻이 아니다.
- **Rationale**: 큰 그림만 귀여운 상태를 피하고 작은 실제 화면에서 젤리·표정·기울기·컵의 가독성을 본다. 정적 합성 포즈와 실제 플레이를 구분하고, 시각 확인 없이 테스트 통과만으로 미술 완료를 주장하지 않는다.
- **Code constraint**: 현 리그186/118은 약1.58등신이므로2등신 재설계의 새 비율을 계획에서 명시한다. 몸통 컴포넌트 밖의 소매·커프스·음영·광택도 포함해 제거 대상을 찾고, 캐릭터 선택 화면의 고정 미리보기 영역에서 새 실루엣이 잘리지 않는지 확인한다.

## D08. 저장·랭킹·배포 경계

- **Keep**: 기존 로컬 기록/수집/설정/닉네임/계정을 삭제하거나 리셋하지 않는다. 새 DB 스키마/광고/로그인 방식/모드/장애물 충돌은 추가하지 않는다.
- **Implementation constraint**: 물리 변경 후 원본·생성된 서버 사본·규칙 버전·합법 입력 골든을 함께 갱신하고 Node/Deno/Chromium에서 검증한다. Hermes/iPhone 미검증은 별도로 표시한다. 현재 로컬규칙9fc10a2a8fdd4085와 실제staging규칙2093a8b42d416f8a의 차이를 보존해 기록한다.
- **Return**: 새 게임 변경을 계획/구현한 뒤 기존P02-T03으로 복귀한다. 새 실제 서버 배포/운영 검증을 완료한 것으로 처리하지 않으며 이번 인터뷰에서 production/Pages/스토어 배포·커밋·푸시를 하지 않는다.

## D09. 코드 조사에서 확인한 사실과 범위 밖 항목

- 현재 입력 가속9.6에 비해 초기 주기 외란 항의 최대 크기는약0.297이고 매끈한 두 파형이다. 이것은 전체 힘이나 인간 난이도와 같은 값이 아니며 쉬운 체감의 가능한 요인이다. 현재 첫 사건의 실제 힘은 플레이 약23.5초 후라 공백이 길다.
- 844×390 화면 초반 가까운 건물 이동은 약18.6px/s였다. 실제점수 속도와 표현 배율을 분리해야90초를 보존하면서 이동감을 높일 수 있다. 위 수치는 인터뷰의 기존 코드 분석/수치 계산이며 새 구현의 측정 결과가 아니다.
- `src/theme/tokens.ts`에는 렌더러에서 쓰지 않는 옛205/118/51/36 치수가 남아 있다. 중복 상수의 정리가 유용할 수 있으나 이번 인터뷰에서 임의로 리팩터링 범위를 추가하지 않는다.
- 기존Supabase 운영/동시성/만료/production 검증은 미완료다. 게임 수정 승인을 곧바로 해당 외부 배포 승인이나 완료로 확대하지 않는다.
