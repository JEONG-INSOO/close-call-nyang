# Decisions: 종료·홈 화면 간소화

- Date: 2026-09-29
- Status: Confirmed

## D01. 종료 화면 버튼과 순서
- **Chosen (user)**: 결과 화면의 ‘다시 도전’을 첫 번째 행, ‘처음으로’를 두 번째 행에 둔다. ‘랭킹등록완료!’를 포함한 랭킹 상태·랭킹·닉네임 설정·기록 공유·캐릭터·설정 표시와 버튼을 제거한다.
- **Chosen (user)**: 기존 ‘광고보고 일어서기’는 유지한다. 사용 가능할 때 위 두 버튼 다음 행에 둔다.
- **Rationale**: 종료 뒤 행동을 짧은 세로 흐름으로 정리하되, 사용자가 명시적으로 보존한 부활 경로는 끊지 않는다.

## D02. 다시 도전 색
- **Chosen (user)**: ‘다시 도전’ 버튼 배경에 이전 ‘랭킹등록완료!’ 알림과 같은 `palette.mint`를 사용한다. 텍스트 대비는 기존 `palette.ink`로 유지한다.
- **Rationale**: 등록 알림은 사라지지만 시각적 강조는 주요 행동으로 옮긴다.

## D03. 홈 및 첫 닉네임 설정
- **Chosen (user)**: 홈에는 랭킹·캐릭터·설정 버튼만 남기고 닉네임 버튼을 제거한다. 첫 실행 안내에서 ‘나중에’를 고르면 설정 화면에 ‘닉네임 설정’을 노출한다. 성공적으로 처음 설정된 뒤에는 설정 화면의 편집 버튼을 숨긴다.
- **Chosen (user)**: 닉네임 변경 금지는 앱 UI 경로에만 적용한다. 현재 Supabase `POST /profile`과 `rank_upsert_profile`의 변경 허용 정책은 이번 작업에서 바꾸지 않는다.
- **Rationale**: 첫 설정을 미룬 플레이어를 막지 않으면서 기존 온라인 서비스의 동작·운영 정책을 유지한다. ‘한 번 설정’은 보안상 서버 불변 보장이 아닌 현재 앱의 UX 제한이다.

## D04. 기존 데이터·정책 보존
- **Chosen (code inspection)**: 결과 화면의 표시/진입점만 제거한다. 내부 랭킹 제출과 실패 시 다음 시작의 대기 처리(`PendingRankingPanel`), 캐릭터 해금 알림, 기존 광고 부활 로직은 유지한다.
- **Chosen (code inspection)**: 설정의 온라인 프로필 삭제는 개인정보 삭제 경로이므로 유지한다. 삭제 후 신규 익명 신원에서 다시 첫 닉네임을 설정할 수 있다.
- **Rationale**: UI 정리로 점수 서버 전송·개인정보 삭제·해금 기록을 우연히 중단하지 않는다.

## Out of scope
- 서버의 닉네임 변경 차단, 데이터베이스 마이그레이션, 공개 웹·TestFlight 재배포, 광고 제공자 연동은 이번 변경에 포함하지 않는다.
- `docs/learning-notes.md` 등 기존 미커밋 변경과 베테랑 T03·iOS P03-T03 미완료 작업을 보존한다.
